## Ground rules
- Swift 6, `SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor`. Pure data/logic types are `nonisolated` (a MainActor class with isolated deinit crashed the test host in sprint 1). Money is `Decimal`, 2dp. `os.Logger` not `print`. No force-unwraps on data paths. No debug hooks or `NSLog`.
- Build: `export DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer`; `xcodebuild -project Thaw.xcodeproj -scheme Thaw -sdk iphonesimulator -derivedDataPath .build/dd-<role> build` (CLEAN before reporting). Project is generated by XcodeGen from `project.yml`; synchronized folders mean new files in `Thaw/` are picked up after `xcodegen generate` (PM owns `project.yml`; ask PM via your report if a setting must change).
- Design system components take plain values only (no model types).
- Light mode only. Colours from `Theme`. Voice: warm, brief, on your side. No shaming copy.

## Decisions
| # | Decision |
|---|---|
| D1 | Payday rule enum: `sameDate(day)`, `lastWorkingDay`, `twiceMonthly(first, second)`, `fixedWait(days)`. Defaults: sameDate(25), review 09:00, fun money S$300, timer threshold S$30, timer 2 days. |
| D2 | State persists as JSON at `Application Support/Thaw/state.json`. `-thawReset` deletes it; `-thawFixture sprint1` seeds the four sprint-1 wants. First launch with no settings shows onboarding (Payday setup). |
| D3 | "Wait" on a want moves `thawsAt` to the following payday. "Keep" sets status `.bought`. Skip stays `.skipped`. |
| D4 | Notification permission is requested on first Add or first Save of settings, never at launch. |
| D5 | Dynamic Type: all text scales via `UIFontMetrics`; at accessibility sizes the payday card and rows stack vertically; every screen scrolls. |
| D6 | Cubi appears only at: Home status face (small), Add success, Payday review header, Skip celebration. Never on lists, settings or errors. |

## Backend (owns `Thaw/Models/**`, `Thaw/Services/**`, `Thaw/Resources/**` except Fonts, `ThawTests/Backend*Tests.swift`)
Task `s2-be-state`, commit tag `[s2-be-state]`. Keep existing `Want`, `WantStore`, `Formatting`, `CoolingRule` call sites compiling (Frontend uses them now); add, don't break.

```swift
nonisolated enum PaydayRule: Codable, Equatable, Sendable {
    case sameDate(day: Int), lastWorkingDay, twiceMonthly(first: Int, second: Int), fixedWait(days: Int)
}
nonisolated struct PaydaySettings: Codable, Equatable, Sendable {
    var rule: PaydayRule; var reviewHour: Int; var reviewMinute: Int
    var funMoney: Decimal; var timerThreshold: Decimal; var timerDays: Int
    static let `default`: PaydaySettings
    func nextPayday(after: Date, calendar: Calendar) -> Date      // review time applied
    func paydayAfter(_ payday: Date, calendar: Calendar) -> Date  // for Wait
}
nonisolated struct FunMoneySummary: Equatable, Sendable {
    let kept: Decimal; let budget: Decimal
    var remaining: Decimal { get }  // budget - kept, may be negative
    var overBy: Decimal { get }     // max(0, kept - budget)
    var fraction: Double { get }    // min(1, kept/budget)
    static func make(keptPrices: [Decimal], budget: Decimal) -> FunMoneySummary
}
```
`Want` gains `thawsAt: Date` (Codable). `WantStore` gains: `settings: PaydaySettings?` (nil = onboarding), `func save(settings:)`, `func decide(id:, keep: Bool)`, `var thawedWants: [Want]` (cooling with `thawsAt <= now` or on-payday wants when `now >= nextPayday`), `init(fileURL: URL?)` (nil = in memory), `static func launch(arguments:) -> WantStore` handling `-thawReset` / `-thawFixture`. `WantStore.payday` stays and derives from settings (default settings if nil). Add `daysUntilNext` based on `Calendar.current`.
